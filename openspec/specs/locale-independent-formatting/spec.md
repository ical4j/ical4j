# Locale-independent formatting

## Purpose

Defines that all iCalendar content generated by ical4j (property values, generated `RRULE` text for timezone transition rules, offsets and durations) uses ASCII digits regardless of the JVM default locale. Numeric `String.format` calls in `src/main` must pin `Locale.US` (or an equivalent root locale) so locales with native digits such as Arabic or Persian cannot leak non-ASCII digits into output or into text that is subsequently re-parsed.
## Requirements
### Requirement: Generated iCalendar content uses ASCII digits regardless of default locale

Numeric values that the library formats into iCalendar content SHALL be rendered with ASCII digits (`0`–`9`) irrespective of the JVM default locale. In particular, the `RRULE` text generated by `TimeZoneLoader` for a `java.time.zone.ZoneOffsetTransitionRule` SHALL be formatted with `Locale.US`.

#### Scenario: Transition rule text under a native-digit locale

- **WHEN** the default locale is `fa-IR`, `ar-EG-u-nu-arab` or `th-TH-u-nu-thai`
- **AND** transition rule text is generated for month 3, week index -1, day `SUNDAY`
- **THEN** the text is exactly `FREQ=YEARLY;BYMONTH=3;BYDAY=-1SU`

#### Scenario: Generated observances are plain ASCII

- **WHEN** the default locale is `fa-IR`
- **AND** transition rules are generated for `Europe/London`
- **THEN** every generated observance serialises using only printable ASCII characters and line breaks
