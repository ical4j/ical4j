## Why

Four long-standing, independently reported robustness defects make iCal4j fail hard on input or environments it should tolerate: a calendar whose `END:VCALENDAR` line carries trailing spaces is rejected (#175, reported 2017), a `RANGE=ALL` parameter on a vendor `X-LOTUS-RECURID` property aborts the whole parse (#617), the first `new Calendar()` throws `ExceptionInInitializerError` on Android/ProGuard builds that strip `META-INF/services` (#125, also #29 and #115), and one remaining `String.format` in generated VTIMEZONE content is not locale-pinned (#458). Each was verified against `develop` (4.4.1-develop-SNAPSHOT) on 2026-10-09 and each has a targeted fix.

## What Changes

- **Trailing whitespace on `BEGIN`/`END` lines is tolerated** (#175). `CalendarParserImpl` configures the tokeniser with space (0x20) as a word character, so `END:VCALENDAR   ` yields the token `VCALENDAR   ` and fails `Expected [VCALENDAR], read [VCALENDAR   ]`. A whitespace-only line following `END:VCALENDAR` is folded onto it by `UnfoldingReader` with the same result. The component/calendar name tokens are now stripped of trailing whitespace before use and comparison. Property-name and value handling is unchanged.
- **Invalid parameter values on experimental (X-) properties no longer abort parsing** (#617). `DefaultContentHandler.parameter()` builds each parameter without knowing the enclosing property, so `Range("ALL")` throws unless the Lotus Notes compatibility hint is set. When the enclosing property has an `X-` name, a parameter whose factory rejects the value is now retained as an `XParameter` with the raw value. Standard properties keep strict behaviour; the Notes hint keeps its current meaning. `PropertyBuilder` gains a public `hasExperimentalName()` query.
- **`AbstractCalendarValidatorFactory` falls back to the default implementation** when no `CalendarValidatorFactory` service registration is visible (#125). Today the static initialiser calls `iterator().next()` on the `ServiceLoader`, so a stripped `META-INF/services` directory turns into `NoSuchElementException` → `ExceptionInInitializerError` on the first `Calendar` construction. A registered provider is still preferred when present.
- **Generated transition-rule RRULE text is formatted with `Locale.US`** (#458). `TimeZoneLoader` was the last numeric `String.format` without an explicit locale; under native-digit locales (`fa`, `ar-EG-u-nu-arab`, …) it produced `BYMONTH=۳`. In practice `Recur` parsing normalised these via `Integer.parseInt`'s Unicode-digit tolerance, so this is a hardening of an otherwise masked defect, consistent with the "pin every `String.format` to `Locale.US`" consensus on the issue. The format is extracted to a package-private `transitionRuleText(...)` helper so it can be tested directly.

None of these change public method signatures. One public method is added (`PropertyBuilder.hasExperimentalName()`) and one package-private static helper (`TimeZoneLoader.transitionRuleText`).

## Capabilities

### New Capabilities
- `calendar-parsing-robustness`: tolerance rules applied by `CalendarParserImpl`/`DefaultContentHandler` to syntactically marginal but unambiguous input — trailing whitespace on `BEGIN`/`END` lines, and parameters on experimental properties whose values are not valid for the standard parameter of the same name.
- `locale-independent-formatting`: iCalendar content generated by the library (here: VTIMEZONE transition-rule RRULEs) SHALL use ASCII digits regardless of the JVM default locale.

### Modified Capabilities
- `calendar-validation`: ADDED requirement that the validator factory lookup degrades to `DefaultCalendarValidatorFactory` when no service registration is visible, instead of failing class initialisation.

## Impact

- `src/main/java/net/fortuna/ical4j/data/CalendarParserImpl.java` — strip trailing whitespace from component-name tokens (two sites).
- `src/main/java/net/fortuna/ical4j/data/DefaultContentHandler.java` — `XParameter` fallback for rejected parameters on X- properties.
- `src/main/java/net/fortuna/ical4j/model/PropertyBuilder.java` — new `hasExperimentalName()`.
- `src/main/java/net/fortuna/ical4j/validate/AbstractCalendarValidatorFactory.java` — `hasNext()` guard with default fallback.
- `src/main/java/net/fortuna/ical4j/model/TimeZoneLoader.java` — `Locale.US` format via `transitionRuleText(...)`.
- Tests: `CalendarParserImplSpec` (new data-driven case), new `ExperimentalPropertyParameterSpec`, new `AbstractCalendarValidatorFactoryTest` (class-loader isolation), new `TimeZoneLoaderLocaleSpec`.
- Consumers: previously rejected inputs now parse; no change for valid input. RevAPI: one added public method, no removals.
- Closes #175, #617, #125, #458; also resolves the ServiceLoader aspect of #29 and #115.
